# Commit

## 1. Inspect

```bash
git status --short
git diff --stat
git diff --cached --stat
```

- Make sure you're on the intended branch (`git branch --show-current`). `main` deploys to GitHub Pages on push.
- Stage files explicitly by path (`git add <paths>`). Don't use `git add -A` blindly.
- Never stage these:
  - `dist/`, `.angular/`, `node_modules/`, `playwright-report/`, `test-results/`
  - stray screenshots
  - a filled-in HubSpot ID unless the user asked for it. HubSpot portal and form IDs are public, but confirm before committing them.
- If `src/styles/_icons.scss` changed, commit it. It's generated by `npm run icons`, and committing it keeps `npm run lint` (`--check`) green.

## 2. Quality gates (fast)

```bash
npm run lint
npm test
```

- If either fails, fix the problem or report it. Don't commit broken code unless the user explicitly says to, and say so in the message body if they do.
- Never use `--no-verify`.

## 3. Message

Use [Conventional Commits](https://www.conventionalcommits.org/):

```
<type>(<scope>): <imperative summary, ≤ 72 chars>

<why, not what — wrap at 72. Mention user-visible changes and anything deliberately left out.>

Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
```

- **Types:** `feat`, `fix`, `content`, `style`, `refactor`, `test`, `docs`, `ci`, `chore`, `perf`.
- **Scopes:** `home`, `about`, `projects`, `cases`, `skills`, `resume`, `contact`, `games`, `layout`, `theme`, `content`, `e2e`, `ci`, `skills-claude`.
- Use `content(...)` for copy and data-only changes in `src/app/content/`.

Pass the message with a heredoc so newlines survive:

```bash
git commit -F - <<'EOF'
feat(games): keep Bug Squash best score across navigation

…

Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
EOF
```

## 4. After

Run `git log --oneline -3` to confirm. Don't push unless asked; pushing is part of the `ship` skill.
